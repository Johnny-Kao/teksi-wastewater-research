## Reproduction

The existing `DatabaseUtils.PsycopgConnection.__exit__` always calls `connection.commit()`, including when Python code inside the `with` raises.

Tests dynamically extract the **unmodified upstream class** from `plugin/teksi_wastewater/utils/database_utils.py`; `psycopg3` talks to an actual PostgreSQL 16 service in GitHub Actions. QGIS application wiring is intentionally not simulated or claimed.

- Baseline: insert completed -> Python ValueError -> upstream context __exit__ -> row PERSISTS.
- Alternative policy: insert -> Python ValueError -> rollback -> row DOES NOT persist.
- Success path commits under both policies.
- SQL UniqueViolation case aborts transaction, no row persists.

All four tests PASS, confirming behavior. The baseline test is expected to PASS when the unwanted behavior occurs; it is not an upstream test failure.

## A-02 structural observation (not reproduced)

`InterlisImporterExporter.interlis_import` commits the main SQLAlchemy session, then calls OD sequence reset, main-cover/node refresh and materialized view refresh, then subclass integrity checks. A later exception could therefore leave committed import data and incomplete post-processing. This is a potential non-atomic orchestration boundary, not a demonstrated bug; a fault-injected real import with legitimate data is required before claiming broken invariants.
